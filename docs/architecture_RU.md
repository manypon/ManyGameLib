# Архитектура

[English](architecture.md) | [Русский](architecture_RU.md)

ManyGameLib — небольшое приложение на Electron из трёх частей с одной runtime-зависимостью (`electron-updater`, нужна только установленным копиям, см. [Обновления](updates_RU.md)). Вся работа с файловой системой и процессами сосредоточена в одном месте (главный процесс), а интерфейс может обратиться к ней только через короткий фиксированный список команд.

```
┌────────────────────────┐   IPC (invoke)    ┌─────────────────────────┐
│ ui/  (renderer)        │ ────────────────▶ │ main.js  (main process) │
│ HTML + CSS + app.js    │ ◀──────────────── │ файлы, процессы, диалоги│
└───────────▲────────────┘   {data}/{error}  └─────────────────────────┘
            │ window.api
┌───────────┴────────────┐
│ preload.js             │  contextBridge: белый список команд
└────────────────────────┘
```

## Процессы и файлы

| Файл | Процесс | За что отвечает |
|------|---------|-----------------|
| `updater.js` | главный (main) | Проверка, скачивание и установка обновлений (подключается из `main.js`) |
| `main.js` | главный (main) | Хранение библиотеки, резервные копии, настройки, журнал, автозапуск, копии картинок, запуск игр, системные диалоги, окно |
| `preload.js` | preload (изолированный) | Отдаёт странице `window.api` с фиксированным набором команд |
| `ui/index.html`, `ui/style.css`, `ui/app.js` | интерфейс (renderer) | Всё, что видит пользователь. Доступа к файлам и процессам нет |

Сборщика и фреймворка нет. `ui/app.js` — один обычный скрипт, который строит DOM небольшим помощником (см. [Интерфейс](ui_RU.md)).

## Модель безопасности

Окно создаётся с параметрами:

- `contextIsolation: true`: страница и preload-скрипт работают в разных мирах JavaScript.
- `nodeIntegration: false` и `sandbox: true`: у страницы нет `require` и API Node.
- Content Security Policy в `ui/index.html`:
  `default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'`.
  Выполняются только собственные скрипты приложения (ни встроенных, ни удалённых). Картинки берутся из приложения или из `data:`-ссылок, потому что изображения игр передаются странице как data URL.

Окно также нельзя увести на другой адрес или открыть из него новые окна (`setWindowOpenHandler` и `will-navigate` блокируют оба случая). `open_external` принимает только ключевые слова `data`, `logs`, `repo` и `release`, но не путь и не адрес, поэтому страница не может с его помощью открыть произвольный файл или ссылку.

Страница не может читать и писать произвольные файлы. Пути к играм и картинкам приходят из системного диалога выбора файла (`pick_file`), а главный процесс перед использованием проверяет каждый путь ещё раз (существование, расширение, размер).

## Контракт IPC

Preload-скрипт отдаёт `window.api` из шести членов:

| Член | Направление | Назначение |
|------|-------------|------------|
| `invoke(cmd, args)` | страница → main, запрос/ответ | Вызывает одну из команд белого списка |
| `pickFile(opts)` | страница → main, запрос/ответ | Открывает системный диалог выбора файла (`pick_file`) |
| `win(action)` | страница → main, в одну сторону | `minimize`, `toggleMaximize`, `close` для собственной шапки окна |
| `onWinState(cb)` | main → страница | Сообщает странице, развёрнуто ли окно, чтобы она нарисовала нужную кнопку |
| `onUpdateState(cb)` | main → страница | Присылает состояние обновления (проверка, скачивание, готово…) |
| `pathForFile(file)` | страница → preload | Путь к файлу, брошенному в окно (`webUtils.getPathForFile`) |

### Команды

`invoke` принимает только эти имена; любое другое отклоняется в preload-скрипте, не доходя до главного процесса:

| Команда | Аргументы | Что возвращает |
|---------|-----------|----------------|
| `get_version` | нет | Строка с версией приложения |
| `get_games` | нет | Массив представлений игр |
| `get_missing` | нет | id игр, файлов которых больше нет |
| `get_assets` | `{ id }` | `{ icon, banner, logo }` в виде data URL (или `null`) |
| `preview_image` | `{ path }` | data URL выбранного файла до сохранения |
| `add_game` | `{ name, exePath, args, images, hero }` | Представление новой игры |
| `update_game` | `{ id, name, exePath, args, images, hero }` | Обновлённое представление игры |
| `launch_game` | `{ id }` | Представление игры с новым `last_played` |
| `toggle_favorite` | `{ id }` | Обновлённое представление игры |
| `remove_game` | `{ id }` | ничего |
| `win_state` | нет | `true`, если окно развёрнуто |
| `get_settings` | нет | Объект настроек |
| `save_settings` | `{ patch }` | Настройки после изменения |
| `reset_settings` | нет | Настройки по умолчанию |
| `set_wallpaper` | `{ path }` | Настройки со своим фоном приложения |
| `clear_wallpaper` | нет | Настройки без своего фона |
| `get_wallpaper` | нет | Свой фон в виде data URL или `null` |
| `get_update_state` | нет | Состояние обновления |
| `check_update` | нет | Состояние после проверки |
| `download_update` | нет | Состояние (`downloading`) |
| `install_update` | нет | ничего; ставит обновление и перезапускает |
| `file_icon` | `{ path }` | Иконка файла игры как data URL или `null` |
| `get_app_info` | нет | Версия, папка данных, версии Electron/Chromium/Node, лицензия, `packaged` |
| `open_external` | `{ target }` | ничего; `target` это ключевое слово `data`, `logs` или `repo` |

Команды настроек описаны на странице [Настройки](settings_RU.md).

### Ошибки

Каждый обработчик в `main.js` обёрнут в `handle()`, и исключение никогда не пересекает границу IPC. Возвращается либо `{ data }`, либо `{ error }` (понятное сообщение на русском). Preload-скрипт превращает это в обычный промис: `{ data }` завершает его с данными, `{ error }` отклоняет его строкой с сообщением. Интерфейс показывает такие сообщения во всплывающих уведомлениях или в форме.

## Окно

- Окно без рамки (`frame: false`), 1280×800, минимум 960×600, тёмный фон, чтобы не было белой вспышки. Показывается по событию `ready-to-show`.
- Шапку окна рисует интерфейс. Верхняя панель и блок с названием приложения — зоны перетаскивания (`-webkit-app-region: drag`); поле поиска и кнопки окна явно помечены `no-drag`.
- Один экземпляр: второй запуск не открывает второе окно, а разворачивает и фокусирует существующее (`requestSingleInstanceLock`, `second-instance`).
- Приложение закрывается вместе с окном (`window-all-closed`).

## Порядок запуска

1. Берём блокировку единственного экземпляра (иначе выходим).
2. Определяем папку данных `%USERPROFILE%\manypon\manygamelib` и создаём `icons`.
3. При необходимости переносим старую библиотеку и загружаем библиотеку. Если файл не читается, в цикле спрашиваем «Повторить / Выйти» (см. [Хранилище](storage_RU.md)).
4. Загружаем настройки (они никогда не мешают запуску, см. [Настройки](settings_RU.md)), пишем первую строку журнала, если он включён, и приводим автозапуск Windows в соответствие с настройкой.
5. Создаём обновлятор, регистрируем обработчики IPC и создаём окно. Если включено «Проверять при запуске», проверка идёт примерно через 4 секунды после готовности окна.
6. Если библиотека была восстановлена из копии, после показа окна один раз выводим уведомление.
