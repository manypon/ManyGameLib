# Картинки и верхний блок

[English](images.md) | [Русский](images_RU.md)

У каждой игры может быть до трёх картинок и несколько настроек верхнего блока. Здесь описано, как картинки хранятся, передаются в интерфейс и остаются согласованными с библиотекой.

## Виды картинок

| Вид | Поле в `games.json` | Для чего |
|-----|---------------------|----------|
| `icon` | `icon_file` | Обложка плитки, значок в списке, обложка справа в верхнем блоке |
| `banner` | `banner_file` | Необязательный фон верхнего блока |
| `logo` | `logo_file` | Необязательный логотип вместо текста названия |

Принимаются форматы PNG, JPG/JPEG, WEBP, ICO, BMP, GIF. Максимальный размер: **8 МБ** на файл (у фона приложения свой лимит 40 МБ, см. [Настройки](settings_RU.md)). Эти проверки выполняет главный процесс для каждой картинки, что бы ни сделал интерфейс.

## Копии, а не ссылки

Когда пользователь выбирает картинку, она **копируется** в папку `icons` библиотеки. Оригинал можно потом удалить или переместить, и у игры останется картинка.

Имена файлов выглядят как `<idИгры>-<вид>-<случайное>.<расширение>`, например `1731234567890-icon-m3k2x9.png`. Случайная часть (текущее время в системе по основанию 36) даёт новое имя при каждой замене картинки, поэтому интерфейс никогда не покажет устаревшую закешированную. В старых библиотеках могут быть имена без случайной части (`<id>.<расширение>`); они по-прежнему работают.

## Изменение картинок: `keep`, `set`, `clear`

`add_game` и `update_game` получают объект `images`. У каждого вида есть `mode`:

```js
images: {
  icon:   { mode: 'set',   path: 'C:\\pics\\cover.png' },
  banner: { mode: 'keep' },
  logo:   { mode: 'clear' }
}
```

| Режим | Результат |
|-------|-----------|
| `keep` (или не указан) | Текущее имя файла остаётся |
| `set` | Файл по `path` проверяется и копируется; его имя заменяет старое |
| `clear` | Поле становится `null` |
| `exe` | Только для `icon`: взять иконку из самого файла игры (см. ниже) |

Работу делает `applyImages()` и возвращает три вещи: новые значения полей, **созданные** файлы и файлы, которые стали **устаревшими** (заменены или убраны).

Правила согласованности:

- Если что-то не удалось при копировании (неверный формат, слишком большой файл, ошибка копирования), все уже созданные файлы удаляются, и весь запрос завершается ошибкой. Наполовину ничего не применяется.
- Если сохранить `games.json` после копирования не удалось, созданные файлы удаляются (список откатывается, см. [Хранилище](storage_RU.md)).
- Устаревшие файлы удаляются только **после** успешного сохранения библиотеки. Неудачное сохранение никогда не стоит старой картинки.
- `remove_game` файлы картинок игры не удаляет: они остаются для корзины, чтобы игра могла вернуться со своими картинками. Они удаляются, когда запись корзины удаляется окончательно (см. [Хранилище](storage_RU.md#корзина)). Собственные файлы игры не затрагиваются никогда.

## Иконка из файла игры

Для `.exe`, `.com`, `.lnk` и `.url` иконку можно взять из самого файла (`extractFileIcon`):

1. Крупная миниатюра от оболочки Windows, до 256 px (`nativeImage.createThumbnailFromPath`).
2. Если не вышло, обычная иконка файла, около 32 px (`app.getFileIcon`). Она маленькая и на большой плитке выглядит мягко, поэтому форма подсказывает выбрать свою картинку для чёткости.

Результат это PNG, который записывается в `icons/` как любая другая картинка (`<idИгры>-icon-<случайное>.png`). Если не сработал ни один способ, запрос завершается ошибкой «Не удалось получить иконку из файла.», и ничего не создаётся.

Форма использует это двумя способами:

- **Автоматически при добавлении игры** (только для `.exe` и `.lnk`): если пользователь не выбирал и не убирал иконку, показывается иконка файла, и она уходит с `mode: 'exe'`. Если затем выбрать файл другого типа, автоиконка убирается. Когда пользователь сам выбрал или убрал иконку, автоматически она больше не подставляется. При правке уже добавленной игры автоиконка не подставляется.
- **Кнопка «Из файла»** (ещё и для `.url`): то же самое по требованию, в формах добавления и правки.

Команда `file_icon` `{ path }` возвращает иконку как data URL для предпросмотра в форме или `null`. При `mode: 'exe'` главный процесс достаёт иконку заново в момент сохранения, поэтому временные файлы не нужны. `prepareImages()` берёт со страницы только `mode` и `path`, но не данные картинки, поэтому страница не может записать произвольные байты в `icons/`.

У типов вроде `.bat` или `.jar` своей иконки нет (Windows вернула бы стандартную иконку файла), поэтому для них её не предлагают.

## Передача картинок странице

Картинки передаются как `data:`-ссылки (base64), поэтому CSP разрешает `img-src data:`.

- `get_games` возвращает лёгкое представление каждой игры: **иконку** в виде data URL и только флаги `has_banner` и `has_logo` для тяжёлых картинок.
- Когда игра становится показанной в верхнем блоке, интерфейс запрашивает её баннер и логотип через `get_assets` и кеширует в памяти. Когда они приходят, верхний блок перерисовывается.
- `preview_image` превращает выбранный в форме файл в data URL до всякого сохранения, чтобы форма показала предпросмотр.

Так основной список остаётся небольшим даже с крупными баннерами.

## Настройки верхнего блока (`hero`)

| Поле | Значения | Смысл |
|------|----------|-------|
| `bg` | `blur`, `banner`, `color` | Фон: размытая иконка, картинка-баннер или цветной градиент, получаемый из названия игры |
| `art` | `true` / `false` | Показывать ли обложку справа в блоке |
| `fit` | `cover`, `contain` | Обрезать обложку под рамку или показать целиком |

`normalizeHero()` работает при каждом сохранении и чтении, поэтому неверные или отсутствующие значения становятся `blur`, `true`, `cover`. Если `bg` равен `banner`, а картинки баннера нет, форма отказывается сохранять и просит выбрать картинку или другой фон.

Без иконки у игры цветная плитка с первой буквой. Оттенок берётся из названия, поэтому между запусками он не меняется.

Фон приложения (картинка за всем интерфейсом) отделён от картинок игр: это встроенная картинка или своя копия `icons\app-wallpaper-<случайное>.<расш>`, см. [Настройки](settings_RU.md). Фон верхнего блока, описанный здесь, можно отключить в настройках (`heroBackground`); сохранённые значения `hero` игры при этом не меняются.

## Поведение формы

Форма добавления и правки хранит для каждой картинки `{ url, mode, path }`: что показано сейчас и что сделать при сохранении. Живой предпросмотр верхнего блока использует тот же код отрисовки, что и настоящий блок (с пометкой предпросмотра и отключёнными кнопками запуска), поэтому пользователь видит именно то, что сохранится.
