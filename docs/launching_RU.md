# Запуск игр

[English](launching.md) | [Русский](launching_RU.md)

Запуском целиком занимается главный процесс (`spawnGame()` в `main.js`). Интерфейс лишь отправляет `launch_game { id }`.

## Что происходит при `launch_game`

1. Находим игру; если id неизвестен, возвращаем ошибку.
2. Если игра уже идёт (у неё есть живая сессия, см. «Состояние «Играет»»), возвращаем её состояние без повторного запуска.
3. Если эту игру запускали меньше 3 секунд назад, сразу возвращаемся без повторного запуска (см. «Защита от повторов»).
4. Если файла больше нет, возвращаем ошибку «файл не найден».
5. Записываем время запуска, затем стартуем процесс.
6. При неудаче снимаем отметку (чтобы пользователь мог сразу повторить) и сообщаем ошибку.
7. При успехе ставим `last_played` в текущее время, сохраняем библиотеку, начинаем следить за процессом ради времени в игре (см. ниже) и возвращаем обновлённую игру.

## Как запускается каждый тип файла

| Расширение | Способ |
|------------|--------|
| `.exe`, `.com` | `spawn` напрямую с параметрами запуска игры, рабочая папка — папка самой игры. Если не вышло (например, Windows требует повышения прав) и параметров нет, запасной путь через оболочку (`shell.openPath`), которая показывает окно UAC |
| `.jar` | Находим `javaw.exe` (см. ниже) и запускаем `javaw -jar <файл> <параметры>` в папке файла |
| всё остальное (`.lnk`, `.url`, `.bat`, `.cmd`, `.msi`, другие файлы) | `shell.openPath`: программа, назначенная этому типу файлов в Windows |

## Параметры запуска

У игры могут быть параметры запуска (`args`), например `-windowed -nolauncher`. Они используются только для `.exe`, `.com` и `.jar`: для остальных типов поле в форме скрыто, а сохранённое значение игнорируется.

- Строка делится на слова по пробелам; текст в двойных кавычках остаётся одним словом (`-path "C:\My Games"` даёт `-path` и `C:\My Games`). Незакрытая кавычка захватывает остаток строки (`parseArgs`).
- Слова передаются процессу списком, а не через командную оболочку. Символы вроде `&` или `|` это обычный текст, поэтому параметр не может запустить другую команду.
- Для `.jar` параметры идут после `-jar <файл>`. Параметры JVM (например, `-Xmx4G`) не поддерживаются: они должны стоять до `-jar`.
- Если прямой запуск не удался и у игры есть параметры, запасной путь через оболочку **не** используется (она не умеет передавать параметры), а в ошибке подсказка запустить игру без параметров или вручную. Это важно для игр, которым нужны права администратора.
- В журнал пишется `[с параметрами]`, но не их содержимое, потому что в параметрах могут быть токены.

Процессы стартуют **отсоединёнными** (detached), с игнорируемым stdio и `unref()`, поэтому игра продолжает работать, если закрыть ManyGameLib, а её вывод никогда не блокирует лаунчер. Рабочая папка — папка игры, потому что многие игры загружают файлы по относительным путям.

## Java для `.jar`

Приложение ищет `javaw.exe` в таком порядке и берёт первый найденный:

0. Путь, заданный в настройках (`javaPath`, см. [Настройки](settings_RU.md)). Если он задан, используется **только** этот файл: неверный путь это явная ошибка («Файл Java из настроек не найден»), а не тихий переход на другую Java.
1. Все папки из `PATH`.
2. `JAVA_HOME\bin` и `JRE_HOME\bin`.
3. Реестр Windows:
   - команда, назначенная для файлов `.jar` (`HKCR\jarfile\shell\open\command`). Путь из неё используется, только если указывает на `javaw.exe`; если `.jar` отдан архиватору, он игнорируется;
   - значения `JavaHome` в `HKLM\SOFTWARE\JavaSoft` и `HKLM\SOFTWARE\WOW6432Node\JavaSoft`.
4. Типичные папки установки внутри Program Files (и вариантов x86 / W6432): `Java`, `Eclipse Adoptium`, `Microsoft`, `Zulu`, `BellSoft`, `Amazon Corretto`, `Semeru`, `Temurin`. Если установлено несколько версий, побеждает самая новая. Версии сравниваются как числа из имени папки, а старая запись `1.8` считается Java 8 (поэтому `jdk-17` новее, чем `jre1.8.0_300`).

Чтение реестра идёт через `reg query` с таймаутом 4 секунды и пропускается вне Windows.

Если ничего не найдено, пользователь получает понятное сообщение («Java не найдена. Установите Java (JRE 8 или новее) или задайте JAVA_HOME»), и **больше ничего не открывается**. Приложение намеренно не откатывается на сопоставление файлов в Windows, потому что на многих компьютерах `.jar` отдан архиватору, и он открыл бы файл как архив вместо запуска.

## Время в игре

Время, проведённое в игре, считается автоматически в `playtime_sec`.

- **Что считается.** Время от старта процесса, который запустил ManyGameLib (`.exe` или `.com` игры, либо `javaw` для `.jar`), до его завершения. Событие `exit` процесса заканчивает сессию, секунды прибавляются к игре и сохраняются (странице об этом сообщает событие `game-updated`).
- **Сессии короче 60 секунд не учитываются**, чтобы игра, вылетевшая сразу, или лаунчер, который открылся и закрылся, не добавляли мусор.
- **Одна сессия на игру.** Если второй экземпляр запущен, пока работает первый, сессию определяет только первый процесс, поэтому время не удваивается.
- **Закрытие ManyGameLib во время игры.** Игра продолжает работать; при выходе (`before-quit`) время до этого момента сохраняется. То, сколько в неё играют после, не учитывается. Если ManyGameLib аварийно завершится, идущая сессия потеряется.
- **Совсем не учитываются:** игры, запущенные через оболочку Windows (`.lnk`, `.url`, `.bat`, `.cmd`, `.msi` и `.exe`, которому понадобился запасной путь с UAC), потому что у нас нет процесса, за которым можно следить. Лаунчеры, которые запускают настоящую игру и закрываются, учитываются только пока работает лаунчер. Для таких игр значение можно задать вручную.
- **Вручную.** В формах добавления и правки есть поле «Наиграно, ч» (часы, дробь через запятую или точку). `add_game` и `update_game` принимают `playtimeSec`: число задаёт значение, `undefined`, `null` или пустое значение оставляют как есть, а неверное число отклоняется («Время в игре задано неверно.»). Форма отправляет значение только если пользователь трогал поле, поэтому автоматическое значение не затирается округлением показанных часов.
- **Журнал.** Каждая засчитанная сессия дополнительно пишется в `sessions.json` (начало и длительность), по нему считается статистика профиля ([Хранилище](storage_RU.md)). Ручное изменение часов сессией не является и не записывается.
- **Отображение.** В виде `12,5 ч`: одна десятая до 100 часов, выше целые часы, «меньше 0,1 ч» для совсем малых значений. Показывается в верхнем блоке, в окне «Об игре» и в сортировке «По времени в игре».

## Состояние «Играет»

Как в Steam, идущую игру нельзя запустить ещё раз. Состояние берётся из сессии, описанной в «Времени в игре»: пока жив процесс, который запустил ManyGameLib, у игры `running: true`.

- `launch_game` для идущей игры ничего не делает и возвращает её состояние.
- Интерфейс показывает «Играет» вместо «Запустить» на большой кнопке, красит ▶ на плитке и кнопку в списке в зелёный и отключает их, а в контекстном меню показывает неактивный пункт «Играет». Двойной клик по плитке ничего не делает.
- Когда процесс завершается (даже после сессии короче 60 секунд), главный процесс шлёт `game-updated` с `running: false`, и кнопки сразу возвращаются в обычный вид.
- **Ограничения.** Отслеживается только процесс, который запустил ManyGameLib. Игры, запущенные через оболочку Windows (`.bat` и другие типы), процесса для наблюдения не имеют и никогда не показываются как идущие; трёхсекундная защита ниже для них работает. Если лаунчер запускает настоящую игру и сам закрывается, игра считается не идущей после выхода лаунчера. После перезапуска ManyGameLib игра, которая всё ещё идёт, как идущая не показывается.

## Защита от повторов

Двойной клик не должен запускать игру дважды, поэтому защита двухслойная:

- **Главный процесс.** Словарь `id игры → время запуска`. Запрос для той же игры в течение `LAUNCH_LOCK_MS` (3000 мс) игнорируется и возвращает текущее состояние игры. Время записывается *до* старта процесса, поэтому два одновременных запроса не могут пройти оба. Неудачный запуск стирает запись. Это защищает от любого источника повторных вызовов, даже неизвестного интерфейсу.
- **Интерфейс.** `launching` помечает игру занятой на те же 3 секунды. Все кнопки запуска этой игры (большая, ▶ на плитке, кнопка в списке) отключаются, а большая кнопка показывает «Запускается…». Неудачный запуск разблокирует сразу. Блокировка переживает перерисовки, потому что кнопки помечаются заново после каждой отрисовки.

Другие игры блокировка никогда не затрагивает.

Блокировка живёт только в памяти; перезапуск приложения её сбрасывает.

## Отсутствующие файлы

`view()` помечает игру `missing`, если её файла нет. На плитке появляется метка «Файл не найден». Интерфейс дёшево перепроверяет (`get_missing` возвращает только id) при каждом возвращении фокуса в окно, поэтому подключённый диск или возвращённый файл убирают метку без перезапуска.

## Журнал

Если в настройках включён журнал, каждый запуск, выбранная Java и каждая ошибка запуска записываются в `logs\manygamelib.log` (см. [Настройки](settings_RU.md)).

## Ограничения

- «Запущена» означает, что процесс стартовал, а не что игра загрузилась. Время в игре не отслеживается.
- Лаунчеры, которые запускают настоящую игру другим процессом, запускаются нормально, но приложению известен только первый процесс.
