# Настройки и внешний вид

[English](settings.md) | [Русский](settings_RU.md)

[← Оглавление документации](README_RU.md)

Страница «Настройки» (боковое меню → Настройки) управляет фоном приложения, верхним блоком, автозапуском, журналом и путём к Java. Настройки лежат в отдельном файле `settings.json` рядом с библиотекой и используют те же приёмы бережной записи, что и библиотека (см. [Хранилище](storage_RU.md)). Здесь описано, как они хранятся, проверяются и применяются.

## Файл

`%USERPROFILE%\manypon\manygamelib\settings.json` создаётся при первом сохранении (на свежей установке файла нет, и приложение просто работает на значениях по умолчанию).

```json
{
  "background": { "mode": "default", "blur": 4, "dim": 40, "file": null },
  "heroBackground": true,
  "autostart": false,
  "logging": false,
  "javaPath": ""
}
```

| Поле | Значения | По умолчанию | Смысл |
|------|----------|--------------|-------|
| `background.mode` | `default`, `custom`, `none` | `default` | Картинка за всем интерфейсом: встроенная, своя или без неё |
| `background.blur` | 0–40 | `4` | Размытие картинки в пикселях |
| `background.dim` | 0–90 | `40` | Затемняющий слой поверх картинки, в процентах |
| `background.file` | имя файла или `null` | `null` | Своя картинка: файл внутри `icons\` (только имя, никогда не путь) |
| `heroBackground` | `true` / `false` | `true` | Есть ли у верхнего блока своя карточка с фоном |
| `autostart` | `true` / `false` | `false` | Запускать вместе с Windows |
| `logging` | `true` / `false` | `false` | Писать `logs\manygamelib.log` |
| `javaPath` | строка до 500 символов | `""` | Конкретный `javaw.exe` для `.jar`; пусто означает «искать автоматически» |

## Чтение, проверка, сохранение

**`normalizeSettings(raw)`** это единственные ворота. Каждое чтение и каждое сохранение проходят через неё, поэтому остальной код может доверять форме данных:

- неизвестные ключи отбрасываются;
- неверный тип или неизвестный режим заменяются значением по умолчанию;
- числа округляются и обрезаются до своего диапазона (`blur` 999 станет 40, `dim` -5 станет 0);
- `background.file` принимается, только если это простое имя файла (`path.basename(x) === x`), поэтому вручную исправленный файл не может указать за пределы `icons\`;
- `mode: custom` без файла становится `default`.

**`mergeSettings(patch)`** накладывает частичное изменение на текущие настройки. Копируются только известные ключи (`heroBackground`, `autostart`, `logging`, `javaPath` и `background.mode/blur/dim`). Страница не может задать `background.file` напрямую: это поле меняют только `set_wallpaper` и `clear_wallpaper`.

**`saveSettings(next)`** пишет `settings.json.tmp`, копирует текущий файл в `settings.json.bak`, затем переименовывает временный файл поверх настоящего (с тем же коротким повтором при занятом файле, что и у библиотеки).

**`loadSettings()`** никогда не мешает приложению запуститься:

| Ситуация | Результат |
|----------|-----------|
| Файла нет | Значения по умолчанию |
| Файл корректный | Используется (после `normalizeSettings`) |
| Файл повреждён (не JSON, не объект) | Переименовывается в `settings.corrupt-<дата>.json`, затем пробуется `settings.json.bak`, затем значения по умолчанию |
| Файл не читается (занят) | Значения по умолчанию на этот сеанс; файл **не** переименовывается, потому что он не повреждён |

В отличие от библиотеки, диалога «Повторить / Выйти» нет: настройки не критичны. Обратная сторона: если файл был занят при запуске и пользователь меняет настройку в этом сеансе, сохранение записывает текущие значения из памяти поверх него.

## Команды

| Команда | Аргументы | Что возвращает |
|---------|-----------|----------------|
| `get_settings` | нет | Объект настроек |
| `save_settings` | `{ patch }` | Настройки после изменения |
| `reset_settings` | нет | Настройки по умолчанию |
| `set_wallpaper` | `{ path }` | Настройки (режим становится `custom`) |
| `clear_wallpaper` | нет | Настройки (картинка убрана) |
| `get_wallpaper` | нет | Своя картинка в виде data URL или `null` |
| `get_app_info` | нет | `{ version, dataDir, repo, license, electron, chrome, node, packaged }` |
| `open_external` | `{ target }` | ничего; `target` это `data`, `logs` или `repo` |

`open_external` получает **ключевое слово**, а не путь или адрес: главный процесс сам сопоставляет `data`, `logs` и `repo` с папкой данных, папкой журнала и страницей проекта. Всё остальное отклоняется, поэтому страница не может через эту команду открыть произвольный файл или ссылку. Окно также не уходит на другие адреса и не открывает новые окна (`setWindowOpenHandler` и `will-navigate`).

## Фон приложения

Режимы:

- **`default`**: картинка, встроенная в приложение, `ui/assets/wallpaper-default.webp` (WebP 1672×941, около 200 КБ).
- **`custom`**: своя картинка пользователя.
- **`none`**: просто тёмный цвет.

«Фон от игры» **не** является режимом всего приложения: собственный фон игры есть только в верхнем блоке (см. [Картинки](images_RU.md)).

### Своя картинка

`set_wallpaper` запускает тот же `copyImage()`, что и для картинок игр (проверка расширения, лимит 8 МБ) с видом `wallpaper`, поэтому копия называется `icons\app-wallpaper-<случайное>.<расш>`. Затем сохраняет настройки с режимом `custom`. Предыдущий файл обоев удаляется только **после** успешного сохранения; если сохранить не удалось, новая копия удаляется и прежнее состояние остаётся. `clear_wallpaper` очищает имя файла, удаляет файл и, поскольку режим `custom` без файла откатывается к `default`, возвращает встроенную картинку. `get_wallpaper` читает файл как data URL; страница просит его, только когда режим `custom`.

### Как это рисуется

В `ui/index.html` есть слой за всем интерфейсом:

```html
<div class="app-bg" id="appBg">
  <div class="app-bg-img"></div>   <!-- background-image + filter: blur(Npx) -->
  <div class="app-bg-dim"></div>   <!-- тёмный слой, opacity = dim / 100 -->
</div>
```

`applyBackground()` в `ui/app.js` задаёт картинку, размытие и прозрачность затемнения и переключает `body.has-bg`. Пока `has-bg` включён, боковая панель и карточки настроек становятся полупрозрачными с лёгким размытием (`backdrop-filter`), и картинка просвечивает. Элемент с картинкой выступает за края на `2 × blur` пикселей с каждой стороны, чтобы размытые края не показывали пустоту. Слой фиксирован и рисуется один раз; прокрутка содержимого его не перерисовывает.

### Ползунки

Ползунок даёт два события. `input` (пока тянем) только вызывает `applyBackground()`: картинка меняется мгновенно, и ничего не записывается. `change` (когда отпустили) один раз вызывает `saveSettingsPatch()`. Так нет ни полной перерисовки страницы, ни записи на каждый пиксель движения. Если сохранить не удалось, страница заново берёт реальные значения из `get_settings`.

## Верхний блок поверх фона

Когда фон включён, живой верхний блок становится отдельной карточкой: отступ 76 px сверху и 40 px по бокам, скруглённые углы, рамка и тень, а внутри затемняющий градиент вместо растворения в странице. Без фона блок остаётся на всю ширину, как раньше. Картинка фона и размытая картинка игры никогда не смешиваются, поэтому у карточки чёткий край.

Переключатель `heroBackground` убирает саму карточку. `body.hero-flat` скрывает `.hero-bg`, рамку и тень, и название, кнопки и обложка лежат прямо на фоне приложения (с мягкой тенью текста для читаемости). Селекторы ограничены `.content > .hero`, поэтому живой предпросмотр в форме добавления и изменения по-прежнему показывает собственный фон игры. Переключатель лишь скрывает его на экране библиотеки; сохранённые настройки `hero` игры не затрагиваются.

## Общие настройки

**Автозапуск.** `autostart` применяется через `app.setLoginItemSettings({ openAtLogin })` и только при `app.isPackaged`. При запуске из исходников (`npm start`) туда попал бы `electron.exe` вместо ManyGameLib, поэтому переключатель в интерфейсе отключён (`get_app_info` возвращает `packaged`). `afterSettingsChange(prev, next)` вызывает это, только когда значение действительно изменилось, а сброс выключает автозапуск. При старте приложение сравнивает `getLoginItemSettings()` с настройкой и исправляет расхождение.

**Журнал.** Когда `logging` включён, `logLine()` дописывает в `logs\manygamelib.log`:

```
2026-11-11T02:25:11.402Z [info] запуск: Cyberpunk 2077 (D:\Games\Cyberpunk\game.exe)
2026-11-11T02:25:40.118Z [error] launch_game: Файл игры не найден: D:\Games\Old\old.exe
```

Записываются запуск приложения (версия, Electron, платформа), запуски игр, выбранная Java, уведомления о восстановлении библиотеки, события настроек (журнал вкл/выкл, сброс) и **каждая ошибка, которую вернула команда IPC** (`handle()` пишет канал и сообщение). Файл ротируется при 1 МБ (`LOG_MAX_BYTES`): он становится `manygamelib.log.old` (хранится один старый файл), и начинается новый. Ошибки записи молча игнорируются, потому что журнал не должен ломать приложение. Когда журнал выключен, ничего не пишется, и папка даже не создаётся. Журнал остаётся на компьютере; в нём есть названия игр и пути к файлам, поэтому посмотрите его, прежде чем отправлять кому-то.

**Путь к Java.** Если `javaPath` задан, `findJavaw()` использует только этот файл. Неверный путь это явная ошибка («Файл Java из настроек не найден»), а не тихий переход на какую-то другую Java. Пусто означает автоматический поиск, описанный в разделе [Запуск](launching_RU.md). Файл выбирается тем же системным диалогом, что и всё остальное.

**Сброс.** `reset_settings` записывает значения по умолчанию, удаляет файл своих обоев, применяет побочные эффекты (автозапуск выключается) и пишет строку в журнал. Игры и библиотека не затрагиваются.

## Страница настроек

`render()` показывает её, когда `state.view === 'settings'` (у пункта бокового меню `data-view="settings"`). Четыре вкладки, запоминаются в `state.settingsTab`:

| Вкладка | Содержимое |
|---------|------------|
| Общие | Автозапуск, журнал (и «Открыть папку», когда включён), сброс |
| Внешний вид | Режим фона, своя картинка, размытие, затемнение, фон верхнего блока |
| Библиотека | Число игр, игры с пропавшим файлом, папка данных, путь к Java, краткие сведения о копиях |
| О приложении | Версия, Electron, Chromium, Node.js, лицензия, ссылка на репозиторий |

Страница собирается из небольших помощников: `settingsCard`, `settingRow`, `toggle`, `slider` и уже существовавшего `segmented`. Данные для «О приложении» и папки данных приходят из `get_app_info` через `ensureAppInfo()`.
