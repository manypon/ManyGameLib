# Хранилище и резервные копии

[English](storage.md) | [Русский](storage_RU.md)

Библиотека — это один JSON-файл и папка с картинками. Цель проста: **список игр должен переживать сбои, заблокированные файлы и повреждения**, а приложение никогда не должно молча стартовать с пустой библиотекой поверх настоящих данных.

## Где лежат данные

`%USERPROFILE%\manypon\manygamelib\`

```
manygamelib/
├─ games.json                       библиотека
├─ games.json.bak                   предыдущая версия, обновляется при каждом сохранении
├─ games.json.tmp                   временный файл на время сохранения (обычно его нет)
├─ games.corrupt-<дата>.json        повреждённый файл, отложенный в сторону (только после проблемы)
├─ settings.json                    настройки приложения (создаётся при первом сохранении)
├─ settings.json.bak                предыдущая версия настроек
├─ settings.corrupt-<дата>.json     повреждённый файл настроек, отложенный в сторону (только после проблемы)
├─ logs/
│  ├─ manygamelib.log               журнал (только когда он включён)
│  └─ manygamelib.log.old           прежний журнал после ротации при 1 МБ
├─ backups/
│  └─ games-<дата>_<время>.json     по одной копии за запуск приложения, хранятся последние 5
└─ icons/
   ├─ <id>-<вид>-<случайное>.<расш> копии иконок, баннеров и логотипов
   └─ app-wallpaper-<случайное>.<расш> свой фон приложения (если выбран)
```

Настройки, фон приложения и журнал описаны на странице [Настройки](settings_RU.md). Они хранятся отдельно от библиотеки, и повреждённый `settings.json` никогда не затрагивает `games.json`.

Время в именах файлов указано по UTC.

## `games.json`

JSON-массив объектов-игр:

```json
{
  "id": "1731234567890",
  "name": "Hollow Knight",
  "exe_path": "D:\\Games\\HK\\hollow_knight.exe",
  "args": "-windowed",
  "icon_file": "1731234567890-icon-m3k2x9.png",
  "banner_file": null,
  "logo_file": null,
  "hero": { "bg": "blur", "art": true, "fit": "cover" },
  "favorite": false,
  "last_played": 1731300000000,
  "playtime_sec": 45000,
  "added_at": 1731234567890
}
```

- `id` — время создания в миллисекундах в виде строки. Если такой уже занят, он увеличивается, пока не станет уникальным.
- `name` обрезается по краям и ограничивается 80 символами.
- Поля `*_file` содержат только имя файла внутри `icons/`, не путь, поэтому папку можно перенести на другой компьютер.
- `hero` нормализуется при каждом чтении: неизвестные значения заменяются на `blur`, `true` и `cover` (см. [Картинки](images_RU.md)).
- `exe_path` — абсолютный путь, выбранный пользователем.
- `playtime_sec` — время в игре в секундах (целое число, не больше 100 000 часов; нет поля значит 0). Оно прибавляется автоматически и может быть задано вручную, см. [Запуск](launching_RU.md).
- `args` — параметры запуска одной строкой (по умолчанию пусто, поля может не быть у старых игр). Из строки убираются переносы и управляющие символы, длина не больше 1000 знаков.
- Время — Unix-миллисекунды.

## Безопасная запись

`saveGames()` действует в таком порядке:

1. Весь список записывается в `games.json.tmp`.
2. Текущий `games.json` копируется в `games.json.bak`.
3. Временный файл переименовывается поверх `games.json`.

Сбой на шаге 1 оставляет настоящий файл нетронутым. Переименование на шаге 3 атомарно в пределах одного тома, поэтому `games.json` всегда либо старый, либо новый целый файл. Переименование повторяется несколько раз (паузы 150, 300 и 450 мс) для ошибок, которые вызывают антивирусы и облачная синхронизация (`EBUSY`, `EPERM`, `EACCES` и подобные).

### `commit()` и откат

Изменения, добавляющие или правящие игру, идут через `commit(next)`: он подменяет список в памяти, сохраняет, а если сохранить не удалось, возвращает старый список. Память и диск поэтому никогда не расходятся. Файлы картинок, скопированные для этого изменения, при неудачном сохранении удаляются (см. [Картинки](images_RU.md)).

Простые изменения (`toggle_favorite`, обновление `last_played` после запуска, `remove_game`) вызывают `saveGames()` напрямую.

## Чтение и восстановление

`loadGames()` различает ситуации:

| Ситуация | Что происходит |
|----------|----------------|
| Файл прочитан и разобран | Список загружается. Если он не пуст, копия кладётся в `backups/` (см. ниже) |
| Файл **занят или не читается** (`EBUSY`, нет доступа…) | Чтение повторяется 4 раза. Если не получилось, выбрасывается ошибка, и приложение показывает окно с кнопками **Повторить** и **Выйти**. С пустым списком оно не продолжает никогда |
| Файл **повреждён** (не JSON или не массив) | Файл переименовывается в `games.corrupt-<дата>.json` (никогда не перезаписывается). Восстанавливается самая новая рабочая копия: сначала `games.json.bak`, затем `backups/` от новых к старым. Уведомление сообщает, что произошло и где лежит повреждённый файл. Если рабочих копий нет, библиотека начинается пустой, повреждённый файл сохраняется, и уведомление об этом говорит |
| Файла **нет** | Если копий нет, это обычный первый запуск (пустая библиотека). Если копия есть, она восстанавливается с уведомлением |

BOM в начале файла (UTF-8) допускается.

Цикл с окном «Повторить / Выйти» также покрывает ошибки создания папки данных.

### Резервные копии

- `games.json.bak` — предыдущее сохранённое состояние. Меняется при каждом сохранении.
- В `backups/` попадает по одной копии за запуск приложения (только если библиотека не пуста). Хранятся только 5 самых новых, старые удаляются.

Копии содержат только список игр, но не файлы картинок. Восстановление не трогает картинки в `icons/`, поэтому восстановленные игры сохраняют свои картинки, пока `icons/` цела.

## Перенос из GameLib

Старые версии хранили данные в `%APPDATA%\gamelib` (или `GameLib`). При запуске, если нового `games.json` ещё нет, а старый есть, старые `games.json` и папка `icons` копируются в новое место. Старая папка никогда не изменяется и не удаляется.

## Защита от дублей

`add_game` и `update_game` отклоняют игру, файл которой уже есть в библиотеке. Пути сравниваются через нормализованный ключ (`pathKey`):

1. В Windows ярлык `.lnk` заменяется своей целью.
2. Если файл существует, берётся его реальный путь (`realpathSync.native`).
3. Путь делается абсолютным и в Windows приводится к нижнему регистру (файловая система нечувствительна к регистру).

Поэтому `D:\Games\a.exe`, `d:/games/A.EXE` и ярлык на этот файл считаются одной игрой.

## Перенос библиотеки

Скопируйте папку `manygamelib` целиком (настройки и свой фон переедут вместе с ней). Пути к играм абсолютные, поэтому на другом компьютере игры должны лежать по тем же путям. Игра с отсутствующим файлом остаётся в списке и показывает метку «Файл не найден».
