# Интерфейс

[English](ui.md) | [Русский](ui_RU.md)

Интерфейс — обычные HTML, CSS и один скрипт `ui/app.js` (около 1400 строк). Фреймворка и шага сборки нет. Здесь описано, как он устроен, и несколько неочевидных решений.

## Состояние

Всё состояние интерфейса хранится в одном объекте:

| Поле | Смысл |
|------|-------|
| `games` | Список, который вернул `get_games` |
| `assets` | `id → { icon, banner, logo }` для тяжёлых картинок, грузятся по требованию |
| `heroId` | Игра, показанная сейчас в верхнем блоке (`null`, если на экране нет верхнего блока) |
| `view` | `library`, `favorites`, `recent` или `settings` |
| `query` | Текст поиска |
| `sort` | `name`, `added` или `played` |
| `layout` | `grid` или `list` |
| `selectedId` | Игра, которую пользователь выбрал для верхнего блока |
| `settings` | Объект настроек из `get_settings` (см. [Настройки](settings_RU.md)) |
| `wallpaper` | Свой фон приложения в виде data URL, загружается только в режиме `custom` |
| `settingsTab` | Открытая вкладка страницы настроек (`general`, `appearance`, `library`, `about`) |
| `appInfo` | Версия, папка данных и версии среды из `get_app_info`, загружается один раз |

Источник истины по библиотеке — главный процесс. После каждой команды интерфейс заменяет обновлённую игру в `state.games` (`upsert`) или перезагружает список (`refresh`).

## Отрисовка

`h(tag, props, ...children)` создаёт DOM-элементы: `class` задаёт имя класса, свойства вида `onClick` становятся обработчиками событий, `html` используется только для статичных SVG-иконок, остальное становится атрибутами. Текст всегда добавляется текстовыми узлами, поэтому названия игр не могут внедрить разметку.

`render()` перестраивает всю область `#content` по `state` и затем возвращает позицию прокрутки. Полная перерисовка проста и достаточно быстра для сотен игр. Случаи, когда её делать *нельзя* (см. «Клики»), обработаны отдельно.

Что показывает каждый экран:

- **Библиотека:** верхний блок, ряд «Недавние игры» (до 8), затем «Все игры» плитками или списком с выбором сортировки.
- **Избранное / Недавние:** простой список плиток с заголовком.
- **Результаты поиска:** заменяют экран, пока поле поиска не пусто.
- **Приветствие:** показывается, когда библиотека пуста. Это сама форма добавления игры, поэтому первый запуск просит добавить первую игру.

### Верхний блок

Верхний блок показывает выбранную игру; если ничего не выбрано, последнюю из запущенных (или первую игру в текущей сортировке, если ничего ещё не запускали). До четырёх точек под ним переключают между кандидатами. Фон, обложка и заголовок следуют настройкам `hero` игры (см. [Картинки](images_RU.md)). Одна и та же функция `heroNode()` рисует и настоящий блок, и живой предпросмотр в форме добавления и правки.

## Клики и двойные клики

На плитке одиночный клик выбирает игру, а двойной запускает. Раньше это ломали две вещи, обе обработаны:

- **Перерисовка заменяла плитку под курсором.** После первого клика весь экран перестраивался, второй клик попадал на новый элемент, и двойной клик не срабатывал. Теперь `selectInPlace()` заменяет только верхний блок и переключает класс `selected` на существующих плитках. Плитки сохраняются, поэтому двойной клик доходит.
- **Прокрутка сдвигала плитки.** Выбор игры прокручивает страницу к верхнему блоку. Эта прокрутка откладывается на 250 мс и отменяется, если следом приходит двойной клик, так что при двойном клике страница никогда не уезжает раньше времени.

В разделах без верхнего блока (Избранное, Недавние, поиск) одиночный клик открывает окно «Об игре». Это окно перекрыло бы второй клик, поэтому там действие одиночного клика ждёт 250 мс и отменяется двойным кликом.

Кнопка ▶ на плитке и контекстное меню останавливают всплытие событий, чтобы не запускать действия плитки. Клавиатура: Tab переходит между плитками, Enter запускает, пробел делает то же, что клик.

## Поиск

Поле поиска обновляет `state.query` после **паузы 150 мс** в наборе, а не на каждую клавишу, потому что каждое обновление перерисовывает экран. Смена раздела или добавление игры очищает поле и отменяет ожидающее обновление, поэтому старый запрос не вернётся. Поиск сопоставляет название игры без учёта регистра как подстроку.

## Кнопки запуска

Каждая кнопка запуска несёт `data-launch-id`. `refreshLaunchButtons()` вызывается после каждой отрисовки и каждого изменения блокировки; она отключает кнопки запускающихся игр и меняет подпись большой кнопки. Часть защиты в главном процессе описана в [Запуске](launching_RU.md).

## Обновление «Файл не найден»

Событие `focus` окна вызывает `syncMissing()`, которая спрашивает у главного процесса id отсутствующих игр и перерисовывает экран, только если что-то изменилось.

## Окна, меню и формы

- **Модальные окна** (добавление, правка, «Об игре», подтверждение) делят один контейнер. Escape или клик по фону закрывает окно, но если в форме есть несохранённые данные (`tryDismiss`), окно остаётся открытым и показывается подсказка; кнопка × закрывает всегда.
- **Контекстное меню** (правый клик или кнопка «⋯»): запустить, избранное, подробнее, изменить, убрать из библиотеки. Повторный клик по той же кнопке «⋯» закрывает меню.
- **Форма добавления и правки** (`gameForm`) хранит своё локальное состояние: выбранный файл, название (подставляется из имени файла, пока пользователь не введёт своё), три картинки и настройки верхнего блока. При отправке она посылает один запрос `add_game` или `update_game`. Ошибки возвращаются текстом и показываются в форме.
- **Уведомления** показывают короткие результаты и ошибки.
- **Удаление игры** требует подтверждения и убирает только запись из библиотеки.

## Страница настроек и фон приложения

Страница настроек это ещё одно значение `view`, её рисует `renderSettings()` с четырьмя вкладками. Слой за интерфейсом (`#appBg`) показывает фон приложения, а `applyBackground()` его обновляет. Ползунки при перетаскивании меняют только стиль, а сохраняют один раз при отпускании, поэтому нет ни перерисовки, ни записи на каждый пиксель. `body.has-bg` и `body.hero-flat` переключают вид боковой панели, карточек и верхнего блока. Всё это описано на странице [Настройки](settings_RU.md).

## Шапка окна

Системная рамка отключена. `ui/app.js` рисует кнопки свернуть, развернуть/восстановить и закрыть, которые отправляют сообщения `win`; главный процесс сообщает странице о состоянии окна, чтобы средняя кнопка показывала нужный значок. Верхняя панель и название — зоны перетаскивания, а интерактивные элементы внутри них помечены no-drag.
