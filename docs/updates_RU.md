# Обновления

[English](updates.md) | [Русский](updates_RU.md)

[← Оглавление документации](README_RU.md)

ManyGameLib умеет проверять GitHub на наличие новой версии, а если приложение поставлено установщиком, то и скачивать и ставить её. Всё это находится в `updater.js` (главный процесс). Интерфейс видит только небольшой объект состояния и несколько команд.

## Два режима

Режим выбирается один раз при запуске:

| Режим | Когда | Что делает приложение |
|-------|-------|-----------------------|
| `installer` | Приложение собрано, и рядом с exe лежит `Uninstall <имя exe>.exe` (его кладёт установщик NSIS) | Само проверяет, скачивает и ставит обновление через `electron-updater` |
| `manual` | Портативная папка (`win-unpacked`, zip) или запуск из исходников | Только сообщает, что вышла новая версия, и открывает страницу релиза |

Портативную папку приложение не обновляет намеренно: подмена файлов запущенной программы в произвольной папке ненадёжна, а пользователь мог её переместить или переименовать.

## Проверка

- **`installer`**: `autoUpdater.checkForUpdates()` читает `latest.yml` из последнего релиза на GitHub.
- **`manual`**: запрос к `https://api.github.com/repos/manypon/ManyGameLib/releases/latest`, который делает главный процесс (`net.fetch`, таймаут 10 с). Тег (`v1.4.0`) сравнивается с текущей версией функцией `cmpVersion()` (только числа, поэтому `1.10.0` новее `1.9.9`).

Предварительные версии и черновики не предлагаются: адрес `latest` их пропускает, а `electron-updater` оставлен с настройкой по умолчанию.

Проверка запускается по кнопке «Проверить» и один раз примерно через 4 секунды после старта, если включено «Проверять при запуске» (настройка `checkUpdates`, по умолчанию включена). Одновременные проверки сливаются в один запрос. Сбои (нет сети, лимит запросов) превращаются в статус ошибки с сообщением и ничего не блокируют.

## Скачивание и установка (режим `installer`)

Ничего не скачивается и не ставится само: `autoDownload` и `autoInstallOnAppQuit` оба равны `false`.

1. «Скачать» вызывает `downloadUpdate()`. Состояние становится `downloading`, интерфейс показывает полоску прогресса.
2. Когда файл скачан и его контрольная сумма (SHA-512 из `latest.yml`) проверена, состояние становится `ready`.
3. «Установить и перезапустить» вызывает `quitAndInstall(true, true)`: тихая установка, затем запуск новой версии.

Библиотека, картинки и настройки лежат в `%USERPROFILE%\manypon\manygamelib`, вне папки установки, поэтому обновление их не затрагивает.

Установщик не подписан цифровой подписью. Обновление проверяется по контрольной сумме из того же релиза: это защищает от повреждённой загрузки, но не от того, кто управляет самим релизом (это добавила бы подпись кода).

## Состояние

`updater.getState()` возвращает:

| Поле | Смысл |
|------|-------|
| `status` | `idle`, `checking`, `none` (последняя версия), `available`, `downloading`, `ready`, `error` |
| `mode` | `installer` или `manual` |
| `current` | Запущенная версия |
| `version` | Найденная более новая версия |
| `progress` | 0–100 при скачивании |
| `error` | Сообщение, когда `status` равен `error` |

Каждое изменение также отправляется странице событием `update-state` (`window.api.onUpdateState`). Во время скачивания страница двигает только полоску прогресса, а не перерисовывает весь экран. Если фоновая проверка нашла новую версию, всплывающее уведомление указывает на «Настройки → О приложении».

## Команды

| Команда | Что возвращает |
|---------|----------------|
| `get_update_state` | Состояние |
| `check_update` | Состояние после проверки |
| `download_update` | Состояние (`downloading`); отклоняется в режиме `manual` и пока проверка ничего не нашла |
| `install_update` | ничего; отклоняется, если статус не `ready` |

`open_external` с ключевым словом `release` открывает `https://github.com/manypon/ManyGameLib/releases/latest`.

## Что нужно релизу

`electron-updater` находит обновление по файлам, прикреплённым к релизу на GitHub. Workflow сборки прикрепляет их все:

| Файл | Назначение |
|------|------------|
| `ManyGameLib-Setup-<версия>.exe` | Установщик, он же содержимое обновления |
| `ManyGameLib-Setup-<версия>.exe.blockmap` | Позволяет скачать только изменившиеся части |
| `latest.yml` | Версия, имя файла и SHA-512 установщика |
| `ManyGameLib-Build.zip` | Портативная версия (обновление её не использует) |

В `package.json` есть `build.publish` (GitHub, `manypon/ManyGameLib`): из-за него electron-builder пишет `latest.yml` и `resources\app-update.yml` (оттуда установленное приложение берёт источник обновлений). Сама сборка идёт с `--publish never`; прикреплять файлы к релизу должен workflow. См. [Сборка](build_RU.md).
